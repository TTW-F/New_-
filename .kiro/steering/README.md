# Steering 文件使用指南

这个目录包含了专家知识库,当你需要处理特定任务时,可以手动加载对应的专家知识。

## 📚 可用的专家知识

### 1. copywriting-expert.md
**用途:** 文案分析、优化、评估

**何时使用:**
- 分析示例文案
- 对比生成文案与示例
- 评估文案质量
- 给出优化建议

**使用方法:**
```
用户: 请分析这个逆袭流文案 #copywriting-expert

[然后我会自动加载文案专家知识]
```

### 2. prompt-engineer.md
**用途:** 提示词设计、优化、调试

**何时使用:**
- 优化提示词
- 解决生成问题
- 设计新的提示词
- 调试提示词效果

**使用方法:**
```
用户: 帮我优化这个提示词 #prompt-engineer

[然后我会自动加载提示词工程知识]
```

## 🎯 典型工作流

### 场景1: 优化逆袭流提示词

```
1. 用户: "分析这10篇逆袭流示例文案" #copywriting-expert
   → 我使用文案专家知识深度分析

2. 用户: "生成3篇测试文案"
   → 我使用当前提示词生成

3. 用户: "对比测试文案与示例" #copywriting-expert
   → 我使用文案专家知识对比分析

4. 用户: "优化提示词" #prompt-engineer
   → 我使用提示词工程知识给出优化方案

5. 用户: "再生成3篇测试"
   → 验证优化效果

6. 重复步骤3-5直到满意
```

### 场景2: 创建新的文案风格

```
1. 用户: "分析这些新风格的示例" #copywriting-expert
   → 提取新风格的特征

2. 用户: "设计一个新的提示词" #prompt-engineer
   → 基于分析结果设计提示词

3. 用户: "测试新提示词"
   → 生成测试文案

4. 用户: "评估效果" #copywriting-expert
   → 评估是否符合新风格

5. 用户: "继续优化" #prompt-engineer
   → 迭代优化
```

## 💡 最佳实践

### 1. 明确指定专家

使用 `#copywriting-expert` 或 `#prompt-engineer` 明确告诉我你需要哪个专家的知识。

### 2. 提供充足的上下文

给我足够的信息:
- 示例文案
- 当前提示词
- 生成的结果
- 遇到的问题

### 3. 迭代优化

不要期望一次就完美,通过多次迭代逐步优化。

### 4. 记录经验

把成功的优化经验记录下来,形成你自己的知识库。

## 🛠️ CLI 工具

为了提高效率,我们提供了一个 CLI 工具来自动化生成和测试流程。

### 安装和配置

```bash
cd prompt-cli
安装依赖.bat
```

然后:
1. 复制 `.env.example` 为 `.env`
2. 填入你的 DeepSeek API Key

### 使用流程

#### 1. 生成测试文案

```bash
测试生成.bat
```

选择流派和数量,CLI 会自动调用 DeepSeek API 生成文案。

#### 2. 在 Kiro 中分析

生成完成后,在 Kiro 中输入:

```
分析这些文案 #copywriting-expert
```

然后复制粘贴 CLI 输出的文案内容。

#### 3. 在 Kiro 中优化提示词

根据分析结果,在 Kiro 中输入:

```
根据分析结果优化提示词 #prompt-engineer
```

#### 4. 迭代优化

修改提示词文件后,运行:

```bash
开始迭代.bat
```

然后回到步骤 1,继续测试。

### 完整工作流

```
CLI 生成文案
    ↓
Kiro 分析文案 (#copywriting-expert)
    ↓
Kiro 优化提示词 (#prompt-engineer)
    ↓
修改提示词文件
    ↓
回到第一步,继续迭代
```

详见 `prompt-cli/README.md`

## 🔧 扩展

你可以创建更多专家知识文件:

- `audience-psychology.md` - 受众心理专家
- `conversion-expert.md` - 转化优化专家
- `style-analyzer.md` - 风格分析专家
- `ab-testing.md` - A/B测试专家

每个文件都应该:
1. 包含 `inclusion: manual` 前置元数据
2. 定义专家的角色和能力
3. 提供具体的方法论
4. 给出实战案例

## 📝 注意事项

1. **Steering 文件不是代码** - 它们是给 LLM 的知识和指导
2. **让 LLM 做智能工作** - 不要用代码做分析,让 LLM 理解和思考
3. **专家知识要深入** - 不是简单的规则,而是深层的理解
4. **持续更新** - 根据实践经验不断完善专家知识
5. **CLI 只负责 IO** - 生成、保存、读取,不做任何分析
